# SEO без ущерба повествованию

Кейс живёт на своём сайте, на Behance, на Dprofile. Текст один, SEO-слой — отдельный, он лежит в `notes.md` и размечается при публикации. Повествование не подчиняется ключевым словам: сначала история, потом обвязка.

## Где референсы провалились

- Shuka, кейс Flowwow: `<title>` — просто «Shuka», `meta description` пустой. Поисковик не понимает, о чём страница.
- Пинкман, «Норма»: `<title>` — «Норма», пять символов, ни типа работы, ни бренда.
- У ONY и CreativePeople title и description заполнены и это заметно: «Рефреш Yota. Быть другими | Агентство ONY», «MyTretyakov — разработка краудфандинговой платформы Третьяковской галереи».
- Подписей к изображениям (`figcaption`) нет ни в одном из 45 кейсов, `alt` пустой у ONY и Shuka. Это самый недооценённый канал: поиск по картинкам.

Мы делаем то, чего не делают они.

## Поля

**Slug** — адрес страницы. Из названия кейса, транслитом, через дефис, без года и без слов «portfolio», «project», «case».

```
Плохо:  /portfolio/251593383
Плохо:  /projects/case-1
Хорошо: /work/arthello-sistema-personazha
Хорошо: /projects/sdelali-redizayn-sayta-geoservisov-yandeksa-dlya-biznesa
```

Пинкман делает правильную вещь: в адресе лежит описание работы, а не номер.

**Title** — до 60 символов. Формула: `Бренд + что сделали | имя или сайт`. Если название кейса само по себе информативно, годится оно плюс уточнение.

```
«Система, собранная заново. Arthello — система персонажа»
«Рефреш Yota. Быть другими | Агентство ONY»
```

Не пиши «Кейс», «Портфолио», «Проект»: этих слов в выдаче достаточно и без тебя.

**Description** — 140–155 символов, одно-два предложения: что было, что сделали, что получилось. Это не лид кейса дословно, а его сжатие с ключевой формулировкой.

```
Плохо:  «Кейс по разработке айдентики для сети магазинов. Смотрите подробности в портфолио».
Хорошо: «Собрали модульную систему персонажа Arthello: три узла, 12 эмоций, производство без перерисовки. Айдентика, гайд, носители».
```

**H1** — название кейса, один на страницу. Никаких `h2` с рубриками (их у нас нет вообще). Абзацы — просто абзацы.

**Alt к каждому изображению** — 8–14 слов, описывает кадр, а не повторяет текст. Пишется в `notes.md` списком по номерам слайдов.

```
01: «Знак Arthello в трёх версиях на жёлтом фоне»
04: «Упаковка с тиснением, тень от листвы на крафте»
```

**Figcaption** — то же, что «Зачем» из описания слайда, переписанное для читателя. У референсов этого нет нигде, и именно эти строки дают индексацию по картинкам и удержание.

**OG-теги** — `og:title`, `og:description`, `og:image` (обложка 1200×630 или 1400×788 4:5–16:9 под площадку). Обложка кейса работает как превью ссылки: если её нет, соцсеть возьмёт первый попавшийся кадр.

**Schema.org** — `CreativeWork` с `name`, `creator`, `about`, `dateCreated`, `genre`. Пять строк разметки, которых нет ни у одного из пяти референсов.

## Ключевые формулировки

Три-пять фраз, которыми тебя реально ищут: `дизайн-система персонажа`, `айдентика для сети магазинов`, `редизайн сайта геосервисов`. Они должны **естественно** попасть в первый абзац и один-два раза в тело.

Правила:
- Не больше одного вхождения на 100 слов.
- Формулировка должна уже присутствовать в тексте по смыслу. Если её приходится вставлять силой — значит, кейс не про это, и ключ не нужен.
- Не склоняй бренд через запятую в скобках: `айдентика (брендинг, фирменный стиль)` — мусор.
- Первый абзац важнее всех остальных: в нём клиент, тип работы и результат.

## Заголовок и поиск

Пользователь хочет название без игривости. Это не мешает SEO: «Ландшафт возможностей. Х5» индексируется по «Х5» и «ребрендинг», если в title добавить тип работы. Название цепляет человека, title цепляет поисковик — они не обязаны совпадать дословно.

## Что писать в notes.md

```
## SEO
slug: /work/arthello-sistema-personazha
title: «Система, собранная заново. Arthello — система персонажа» (58)
description: «…» (149)
H1: Система, собранная заново
og:image: обложка 1400×788

## Alt
01: …
02: …

## Figcaption
01: …
02: …

## Schema.org
{ "@type": "CreativeWork", "name": "...", "creator": "...", ... }

## Ключевые формулировки
- система персонажа
- айдентика для магазина
- модульный персонаж
```

## Чего не делать

- Не набивать ключи в текст. Читатель чувствует это раньше поисковика.
- Не делать отдельный «SEO-текст» под кейсом: это устаревшая практика и она портит страницу.
- Не менять ради ключей название кейса.
- Не ставить `alt` вида `image1`, `картинка`, `фото дизайн`.
- Не забывать про скорость: 20 изображений по 4 МБ убивают поведенческие факторы сильнее, чем любой title. Отдавай WebP, 1600 px по длинной стороне.
