# case-editor-skill

Скилл для ИИ-агента: собирает кейс в портфолио дизайнера на уровне топовых студий — сюжет по ABT, человеческий текст, обложка из реальных материалов, послайдный визуальный сценарий, SEO и короткая версия для площадок.

Написан под дизайнера широкого профиля: UI/UX, веб, мобильные приложения, продуктовые дизайн-системы, брендинг, брендбуки, коммуникационные системы. Работает для всех: внутри четыре архетипа с разными осями истории.

Сделан на разборе 45 кейсов пяти студий — Shuka, ONY, Пинкман, OTVETDESIGN, CreativePeople — и на разборе портфолио автора.

## Что на выходе

Три файла на проект:

- **`<проект>-case.md`** — готовый кейс: название, лид, текст, на местах изображений и видео — подробные описания в квадратных скобках.
- **`<проект>-short.md`** — 150–200 слов для Behance и Dprofile, конфликт сохранён.
- **`<проект>-notes.md`** — SEO-поля, alt, производственный план, вырезанные из кейса факты, чек-лист.

## Как это выглядит

```
# Персонаж из трёх деталей. Arthello

[📷 00 · 4:5 · Обложка: жёлтый фон, контурный Артик в треть высоты кадра,
справа вертикальная строка капсом. Текст в кадре: «Arthello. Система
персонажа». Зачем: узнаваемая деталь раньше, чем читатель узнает проект.]

У сети магазинов уже был маскот, совёнок Артик. Он жил странно: на сайте —
плоская картинка, в соцсетях — объёмная иллюстрация, на мерче — третий вариант.

[📷 01 · 1:1 · Три версии Артика рядом на нейтральном фоне…]

Запрос звучал как «сделайте персонажа», но персонаж был. Не было языка,
на котором его используют.
```

Описание кадра содержит пять обязательных полей: номер, пропорция, что в кадре, текст в кадре, зачем. Без «зачем» кадр в сценарий не попадает.

## Как пользоваться

Скилл ставится в агента как обычный скилл: папка `skills/case-editor-skill/` целиком кладётся в каталог, откуда агент читает скиллы. У каждой платформы он свой — его лучше сверить с документацией своего агента. Внутреннее устройство одинаковое везде: `SKILL.md` с frontmatter и папки `references/` и `scripts/`.

Дальше — просто просьба:

```
Сделай кейс по проекту Arthello
```

Агент проведёт по фазам:

1. **Брифинг** — вопросы о проекте, максимум шесть за раз. Просит Figma через Figwright MCP или скриншоты, объясняя зачем.
2. **Инвентаризация** — таблица артефактов: что есть, можно ли показывать. Чего нет в таблице — не может появиться в описании кадра.
3. **Сюжет по ABT** — 3–5 тактов И → НО → ПОЭТОМУ. Вы утверждаете сюжет до того, как появится первый абзац.
4. **Название, объём, обложка** — пять вариантов названия, объём по объективному критерию (8+ артефактов и конфликт с последствиями → 700 слов, иначе 300), три концепции обложки.
5. **Текст** — черновик, проход humanizer, типографика. Заголовков-рубрик нет ни одного.
6. **Визуальный сценарий** — послайдное описание с производственным планом.
7. **SEO и короткая версия.**
8. **Приёмка** — сначала проверка фактов по списку утверждений, потом чек-лист на 25 пунктов.

Ворота: без вашего «да» после сюжета, названия с обложкой и сценария агент дальше не идёт.

## Принципы

**Ничего не выдумывать.** Каждый факт и каждый кадр опирается на рассказ пользователя или артефакт из инвентаря. Нет данных — вопрос, а не догадка.

**Сначала сюжет, потом текст.** Писать в неутверждённый сюжет — выброшенная работа. Главная ошибка кейсов: интересный проект без конфликта.

**Заголовков-рубрик нет.** «Контекст», «Что сделано», «Итог» — шаблон среднего уровня: есть у Пинкман и OTVET, отсутствует у ONY, CreativePeople и Shuka. Читателя ведут абзацы и кадры.

**Подписи к кадрам.** У всех 45 разобранных кейсов `figcaption` пуст, а `alt` у ONY и Shuka — пустая строка. Это наше преимущество: индексация по картинкам и удержание.

**Честное трение.** Ограничения, сроки и «не всё шло гладко» продают сильнее гладкого отчёта. Единственная цитата клиента на 45 кейсов — та, где он признаёт сложности (Dodo Brands у ONY).

## Личный блок

`references/video-cheap.md` — про то, как делать видео за час, а не за неделю: запись скролла, параллакс из одного слоя, сборка знака, съёмка на телефон. Это личное ограничение автора, а не часть метода. Если моушен для вас не проблема — удалите файл и строку про него в `SKILL.md`, остальное продолжит работать.

## typograph.py

```
python scripts/typograph.py case.md            # отчёт
python scripts/typograph.py case.md --write    # переписать
python scripts/typograph.py case.md --check    # только проверки, exit 1 при замечаниях
```

Расставляет неразрывные пробелы после предлогов, между числом и словом, кавычки-ёлочки, тире, убирает двойные пробелы. Зависимостей нет, Python 3.8+.
